# Identgineer

A full stack identity and tracking platform, built as a pnpm monorepo.

- **Identity**: user accounts, sign-in and sessions, and brand identity (brand kits that drive
  themes).
- **Tracking**: privacy-first, consent-first analytics events.
- **UI**: Stencil.js web components (`idg-` prefix) and a Stencil website with a sandbox.
- **CMS**: generated by [camis](https://github.com/hynding/camis). Strapi locally, strapi-php
  (camis' Filament target with `apiStyle: "strapi"`) on shared hosting.

Built with HTML5, CSS3 design tokens and strict TypeScript.

## Variation axes

The UI has four independent, interchangeable axes. Each is set as an attribute on the root
element and takes one of eight values (`data-theme` also any theme generated from a brand kit), so
any combination can be mixed freely.

| Attribute     | Axis            |
| ------------- | --------------- |
| `data-theme`  | Color theme     |
| `data-design` | Design language |
| `data-layout` | Page layout     |
| `data-ux`     | UX mode         |

Adopting them in a page or an app: [plain HTML](docs/variations/plain-html.md),
[React](docs/variations/react.md), [Vue](docs/variations/vue.md) and
[Angular](docs/variations/angular.md).

## Identity components

Sign-in, registration, password reset, the profile, a session guard and a user menu are web
components that take the identity client of `packages/identity`. Guides:
[plain HTML](docs/identity/plain-html.md), [React](docs/identity/react.md),
[Vue](docs/identity/vue.md) and [Angular](docs/identity/angular.md), and the
[security notes](docs/identity/security.md).

## Consent components

A consent banner and a preferences panel are web components that take the consent object of the
tracker of `packages/tracking`: the banner never asks under Global Privacy Control or Do Not
Track, gives "Decline" and "Accept analytics" the same weight, and never blocks the page. Guides:
[plain HTML](docs/consent/plain-html.md), [React](docs/consent/react.md),
[Vue](docs/consent/vue.md) and [Angular](docs/consent/angular.md), and
[the rules the banner follows and why](docs/consent/rules.md).

## Dashboard components

A property picker, stat and sparkline figures, and a paged, sortable event table are web
components that take their data as properties and never fetch: the page asks a `DashboardSource`
(the typed seam a server implements over the authenticated API, which enforces who owns what) and
hands the answers over. Everything they show from the public internet is drawn as neutralised
text. Guides: [plain HTML](docs/dashboard/plain-html.md), [React](docs/dashboard/react.md),
[Vue](docs/dashboard/vue.md) and [Angular](docs/dashboard/angular.md), and
[what the source must enforce and how text is treated](docs/dashboard/rules.md).

## Brand themes

A brand kit (name, colours, a font pairing, corners and tone) becomes a theme of its own:
`packages/brand` checks the kit, derives a light and dark palette that passes the same contrast
checks as the built-in themes, and emits it as CSS scoped to `data-theme="<your id>"` and as DTCG
tokens. Its corners are a preference that designs may decline: the square designs (brutalist,
editorial, pixel) keep their own. A kit's logo and mark are SVG uploads, rebuilt by a strict,
dependency-free sanitiser into inert SVG (an allowlist of elements and attributes, no script,
handlers, external references or `foreignObject`, and bounds on what drawing and painting it may
cost) and
shown through `<img>`. See
[packages/brand/README.md](packages/brand/README.md).

## Tracking

`packages/tracking` is a consent-first, privacy-first event tracker: nothing is sent or stored
until the visitor grants consent, Global Privacy Control and Do Not Track are honoured, only the
events the page declares are collected, and URLs are reduced to a path. See
[packages/tracking/README.md](packages/tracking/README.md) for what is collected, the consent
model, the options, the wire format and what the collecting server must enforce.

## Prerequisites

- Node.js 22 or newer (see `.nvmrc`)
- pnpm 10 (pinned in `package.json` via `packageManager`; enable with `corepack enable`)

## Common commands

```sh
pnpm install       # install workspace dependencies
pnpm format        # format with Prettier (format:check to verify only)
pnpm lint          # ESLint with type-aware typescript-eslint
pnpm typecheck     # tsc across every workspace package
pnpm test          # Vitest
pnpm build         # build every package that defines a build script
pnpm cms:generate  # camis dry run for the CMS (also cms:validate, cms:build); needs CAMIS_DIR
pnpm contract:live # the identity SDK against a generated strapi-php backend; needs CAMIS_DIR and PHP 8.3 (Composer for the first run)
```

`pnpm test` runs without camis, PHP or a network; `pnpm contract:live` is run by hand (CI has no
camis checkout). See [packages/identity/README.md](packages/identity/README.md#live-contract).

See [cms/README.md](cms/README.md) for the content model, roles and how camis is run.
