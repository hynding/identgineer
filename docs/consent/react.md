# Consent components in React

The consent elements are custom elements that take the tracker's consent object as a JavaScript
property, `consent`. React needs nothing special for them, only a ref: React 18 would write an
object prop as the attribute `consent="[object Object]"`, and React 19 does the same while the
element is not yet defined. Create one tracker for the app, hand `tracker.consent` to both
elements, and read [rules.md](./rules.md) for what the banner does and why.

## 1. One tracker and the components

```ts
// tracking.ts
import { createTracker } from "@identgineer/tracking";

export const tracker = createTracker({
  endpoint: import.meta.env.VITE_COLLECT_URL,
  writeKey: import.meta.env.VITE_WRITE_KEY,
  consentVersion: 1,
  autoPageViews: true,
  events: { signup_completed: { properties: { plan: "string" } } },
});
```

```tsx
// main.tsx
import { defineCustomElements } from "@identgineer/components/loader";

void defineCustomElements();
```

`createTracker` is safe to import and call without a DOM, but nothing can be recorded there:
create it, and call `defineCustomElements()`, in the browser only. Load `/tokens/index.css`, and
put the pre-hydration rule from
[plain-html.md](./plain-html.md#1-load-the-tokens-and-the-components) in a stylesheet.

## 2. Types for JSX

`Components` is generated by the components package. Declare the elements you use:

```tsx
// consent-elements.d.ts
import type { Components } from "@identgineer/components";
import type { DetailedHTMLProps, HTMLAttributes } from "react";

type Element<T> = DetailedHTMLProps<HTMLAttributes<HTMLElement>, HTMLElement> & Partial<T>;

declare module "react" {
  namespace JSX {
    interface IntrinsicElements {
      "idg-consent-banner": Element<Pick<Components.IdgConsentBanner, "placement" | "preferences">>;
      "idg-consent-preferences": Element<Pick<Components.IdgConsentPreferences, "modal">>;
    }
  }
}
```

## 3. A hook that hands over the consent object and listens

```tsx
// use-consent-element.ts
import { useEffect, useRef } from "react";
import { tracker } from "./tracking";

/**
 * A ref for a consent element: it gets `tracker.consent` and `properties` as properties, and
 * `listeners` as event listeners, removed again when the component goes.
 */
export function useConsentElement<T extends HTMLElement>(
  properties: Record<string, unknown> = {},
  listeners: Record<string, (event: CustomEvent) => void> = {},
) {
  const ref = useRef<T>(null);
  useEffect(() => {
    const element = ref.current;
    if (!element) return;
    Object.assign(element, properties);
    (element as HTMLElement & { consent?: unknown }).consent = tracker.consent;
    const entries = Object.entries(listeners).map(
      ([type, listener]) => [type, (event: Event) => listener(event as CustomEvent)] as const,
    );
    for (const [type, listener] of entries) element.addEventListener(type, listener);
    return () => {
      for (const [type, listener] of entries) element.removeEventListener(type, listener);
    };
  });
  return ref;
}
```

The effect sets the consent object on every render, which costs nothing: the element ignores one
it already has. The other properties are set on every render too, so keep their values stable (a
module constant or `useMemo`).

## 4. The banner and the preferences

Render the banner **last in the body** of the page (a bottom banner sticks to the bottom of the
window from there; see [placement](./rules.md#placement-and-space)). In a single-page app that is
the last child of the root layout, outside any element with `overflow`:

```tsx
import type { ConsentChangeDetail } from "@identgineer/components";
import { useRef } from "react";
import { useConsentElement } from "./use-consent-element";

export function ConsentBanner() {
  const ref = useConsentElement<HTMLElement>(
    {},
    {
      idgConsentChange: (event) => {
        const { state } = event.detail as ConsentChangeDetail;
        console.debug("the visitor chose", state);
      },
    },
  );
  return (
    <idg-consent-banner ref={ref} preferences="preferences-dialog">
      <a slot="policy" href="/privacy">
        Privacy policy
      </a>
    </idg-consent-banner>
  );
}

export function PrivacySettings() {
  const dialog = useRef<(HTMLElement & { open: () => Promise<void> }) | null>(null);
  const inline = useConsentElement<HTMLElement>({ headingLevel: 3 });
  const modal = useConsentElement<HTMLElement>({});
  return (
    <section aria-labelledby="privacy-title">
      <h2 id="privacy-title">Your privacy settings</h2>
      <idg-consent-preferences ref={inline} />
      <idg-consent-preferences id="preferences-dialog" ref={modal} modal />
      <button type="button" onClick={() => void dialog.current?.open()}>
        Open the settings in a dialog
      </button>
    </section>
  );
}
```

For every change, wherever it came from, subscribe to the tracker instead of the elements:

```tsx
import { useEffect, useState } from "react";
import { tracker } from "./tracking";

export function useConsentState() {
  const [status, setStatus] = useState(tracker.consent.get());
  useEffect(() => tracker.consent.onChange(setStatus), []);
  return status;
}
```

## 5. Text

`labels` is a property too. Pass a partial object of strings, which is merged over the English
defaults, and keep it stable as above:

```tsx
const GERMAN = { labels: { accept: "Analyse zulassen", decline: "Ablehnen", choose: "Auswählen" } };

const ref = useConsentElement(GERMAN);
```

## 6. Server rendering

The elements draw nothing on the server, and the tracker records nothing there. Create the
tracker and call `defineCustomElements()` on the client only, for example in a `"use client"`
module in Next.js. The server's HTML then has the bare tags, which the pre-hydration rule keeps
out of sight until they hydrate.
